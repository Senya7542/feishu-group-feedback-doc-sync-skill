# 自动化实现

生成或修改本地同步自动化时读取本文件。

## 本地文件结构

在项目目录里创建类似结构：

```text
tools/<project>_feedback_sync.py
tools/<project>_feedback_supervisor.py
tools/install_<project>_feedback_watcher_task.ps1
.<project>_feedback_sync/
  state.json
  watcher.lock
  watcher-heartbeat.json
  supervisor-heartbeat.json
  logs/
  media/
  tasks/
```

状态和媒体缓存放在项目工作区内，不要放到全局临时目录。

## 同步脚本职责

同步脚本需要：

- 从配置或生成的常量读取 `CHAT_ID`、`TARGET_DOC`、`ACTIVE_PHASE_TITLE`、`PLANNER_OPEN_IDS`、`SELF_OPEN_IDS`。
- 如用户指定某些同事的无标签反馈也应同步，增加 `COLLEAGUE_OPEN_IDS` 或等价配置，并只对明确反馈消息放行。
- 用 `lark-im` 拉取最近群消息。
- 处理前按消息位置或时间排序。
- 先识别视频消息并创建版本区块，但只接受配置的项目 owner/用户本人发送的视频；策划、同事或其他成员的视频标记为参考视频并写入已处理状态，不要创建版本，也不要更新“最近版本”。
- 再识别文字/post 类型反馈，让反馈挂到最近的上一个视频版本。
- 识别策划/设计人员纯图片消息时，检查下一条消息是否来自同一人且是反馈说明文字；如果成立，把图片消息和文字消息合成一条反馈记录，图片来自图片消息，条目来自文字消息，并把文字消息标记为配对处理避免重复。
- 从 IM 下载视频和图片资源。
- 用 `lark-doc` 把媒体上传到飞书文档。
- 回读插入后的媒体块 XML，再重新放进目标排版。
- 维护已处理消息 ID、版本元数据、反馈记录和内容 hash。
- 新版本插入后立即回读并保存对应标题块 ID；只有标题块可读时才把视频消息标记为处理成功。
- 每轮轮询刷新文档标题映射；已知版本缺少标题块时，从原视频消息或本地媒体缓存自动重建版本区块，并合并保留已有反馈 ID、制作会状态等版本元数据。
- 当消息带 `制作会反馈` 标签时，在对应版本元数据中记录制作会展示状态，例如 `presentation_context = "制作会"`，并重渲染该版本标题、本版定位框和策划反馈标题。
- 所有正式反馈都写入 `feedback_records` 后统一重渲染，不要把无图文本反馈直接 append 到文档里；否则下一次重渲染会漏掉 append 旁路里的内容。
- 给反馈记录存储来源类型，例如 `self_summary`、`self_supplement`、`planner`、`colleague`。同一版本一旦存在用户本人 `反馈整理/整理反馈` 记录，正文和反馈图片只渲染该用户整理记录，以及整理记录之后的用户本人 `反馈补充/补充反馈`；没有用户整理记录时，才渲染策划/同事记录。
- 把渲染异常的消息 ID 留在 `failed_feedback_message_ids` 或等价失败队列；内容 hash 未变化不能阻止失败重试，只有文字和图片重新渲染成功后才能清除失败标记。
- 更新同步状态框，最新更新时间精确到分钟。

## 反馈图片规则

反馈图片必须走和编辑反馈相同的“记录式渲染”路径。

必需行为：

1. 从消息内容里提取图片 key，同时兼容 `[Image: img_xxx]` 和富文本 `post` 的 `![Image](img_xxx)`。
2. 从 IM 下载每张图片。
3. 上传到飞书文档。
4. 把上传后的图片 XML 或 source token 存入反馈记录。
5. 按消息顺序把所有反馈图片渲染到视频下方。
6. 再次同步时，如果 image key 没变，复用已存的图片 XML。
7. 只要消息被分类为正式反馈，即使没有显式“反馈整理”标签，也要允许进入记录式同步；图片标注反馈不要因为缺少传统反馈关键词而被跳过。
8. 对“纯图片 + 紧跟说明文字”的配对反馈，反馈记录最好使用图片消息 ID 作为主记录 ID，内容 hash 同时覆盖图片 key 和说明文字；如果旧版本曾经把后续文字单独同步成无图反馈，要先删除旧文字记录，再按配对记录重渲染。
9. 配对反馈必须保持幂等：如果图片消息主记录的内容 hash 没变，且后续文字消息没有残留旧记录，不要每轮都把版本加入重渲染队列，否则飞书前端会在删除/插入瞬间出现反馈短暂消失又恢复的闪烁。
10. 清洗反馈正文时移除两种图片标记，并删除图片后由空富文本列表留下的孤立编号（例如末尾只有 `1.`），避免占位符进入复选框。

## Watcher

watcher 需要：

- 每 30-60 秒运行一次同步。
- 用 lock 文件保证同一时间只有一个 watcher 处理文档。
- 写 heartbeat JSON，包含状态、PID、chat ID、目标文档、轮询间隔和更新时间。
- 日志写到项目本地文件。
- 正常运行时不要弹出可见控制台窗口。

Windows 上优先使用：

- `pythonw.exe` 启动计划任务 supervisor
- `subprocess.CREATE_NO_WINDOW`
- 设置为登录后自动运行的隐藏计划任务
- supervisor 在 watcher heartbeat 过期时自动重启 watcher

安装计划任务前：

- 停掉同项目旧 watcher/supervisor 进程。
- 删除过期 heartbeat。
- 先手动同步成功一次。

## 验证

始终用新命令验证：

- 编译同步脚本，例如 `python -m py_compile tools/<project>_feedback_sync.py`。
- 手动运行一次同步。
- 回读最新版本区块，确认视频、反馈标题和图片存在。
- 验证本地版本记录中的标题块 ID 与文档真实标题一致；不能只检查日志或本地状态。
- 再运行一次同步，确认不会重复插入。
- 安装 watcher 后检查计划任务状态和 heartbeat。

## 常见失败

- 视频出现但反馈没有出现：分类规则太严格、策划 `open_id` 缺失，或反馈消息在视频之前。
- watcher 正常、状态里有新版本，但文档没有该版本：插入后没有回读验收，导致状态与文档分叉；应重建缺失版本并恢复其反馈记录。
- 反馈记录和图片 source 已写入状态，但正文没更新：首次渲染失败后消息被标成已处理，且内容 hash 相同触发了提前返回；失败队列必须覆盖“内容未变化”的幂等分支并强制重渲染。
- 策划参考视频被误建成新版本：版本视频发送者没有限定为项目 owner/用户本人，导致后续反馈挂到了错误版本。
- 用户已经发“反馈整理”，文档还显示零散策划/同事反馈：缺少 `self_summary` 优先级过滤，或反馈图片渲染没有复用同一套可见记录过滤。
- 用户发“反馈补充”但文档不显示：补充记录被标成普通 `self` 后被 `self_summary` 过滤掉；应标成 `self_supplement`，并在存在整理稿时只显示整理稿之后的补充。
- 同事反馈少了第一条：文本清洗用过宽的 `@\S+` 删除 @ 提及时，把 `@某人1.反馈内容` 整段吃掉；应先处理“@ 后紧贴编号”的情况，只删除 @ 名称并保留编号反馈。
- 策划图片反馈没有出现：分类器只认“需要/优化/调整”等关键词，漏掉了“图片 + 位置说明”的标注型反馈。
- 策划先发纯图片、后发说明文字时图片没有出现：同步器没有做相邻消息配对，导致纯图片被忽略、文字被单独入库或被短句规则过滤。
- 策划短句反馈没有出现：关键词表缺少“速度 / 移速 / 节奏 / 时间点 / 位置 / 建模 / 大一点 / 小一点 / 出场 / 提前 / 延后”等运动、画面和模型要求词。
- 最新版本的塔角度、射击频率或 CD 反馈没有出现：关键词表缺少“角度 / 频率 / 保持 / 缩短 / CD / 转”等塔行为要求词，或把“看下能不能保持……”按普通问句过滤了。
- “反馈补充 / 补充反馈 / 制作会反馈”没有出现：显式反馈标签列表或文本清洗标签列表漏掉标签，导致消息被处理但未入记录，或整段被塞进一个 checkbox。
- “制作会反馈”文字出现了但样式没变：只把它当成普通策划反馈追加了，没有给版本写入制作会展示状态，或没有重渲染版本标题、定位框和 `制作会反馈：` 标题。
- 数值小数被拆成错误反馈项：编号拆分正则把 `0.9` 里的 `0.` 当成编号；编号分隔符后面如果还是数字，应视为小数而不是新条目。
- 带“那么 / 这么”的策划反馈被跳过：提问检测把单独的“么”当成疑问标记，应该改成更精确的问句检测。
- 指定同事的反馈没有出现：该成员没有加入 `COLLEAGUE_OPEN_IDS`，或无标签消息被普通讨论过滤规则提前拦截。
- 普通协作消息误进同事反馈：可信同事白名单规则过宽；无标签同事消息应限制为多条编号反馈或带图明确反馈。
- 文字反馈出现但图片缺失：图片只在显式反馈路径处理；带图片的正式反馈必须走记录式同步。
- 策划和同事的富文本带图反馈同时漏掉：图片提取器只支持 `[Image: img_xxx]`，没有兼容 `post` 返回的 `![Image](img_xxx)`，导致带图判定和图片上传一起失效。
- 文档重复内容：没有记录消息 ID/hash，或编辑消息被追加而不是重新渲染。
- 反馈刚补上又短暂消失：配对图片反馈的幂等判断有问题，未变化的“图片 + 文字”每轮都触发重渲染；应只在内容 hash 变化或清理旧文字记录时重渲染。
- 每分钟弹控制台窗口：计划任务正在可见启动 `python.exe` 或 PowerShell；改成隐藏任务和 `pythonw.exe`。
- 新视频进了旧阶段：阶段锚点搜索没有限定 `ACTIVE_PHASE_TITLE`。
